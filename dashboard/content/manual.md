# AI CostScale 使用說明

這份說明分成兩半。**前三節是「該做什麼、怎麼做」**，照著按就好；**後面各節是「每一頁在回答什麼問題、數字該怎麼讀」**，需要時再翻。

讀者是這個後台的擁有者——也就是你。要交給專案端的東西另有一份：`doc/GUIDE-接入-AI-CostScale-閘道.md`，那份是寫給專案或專案的 AI 看的。

---

## 開始之前

### 這套系統在做什麼

你的每一個專案原本各自拿著各家的原廠金鑰去打 AI。那樣有三件事做不到：不知道哪個專案花了多少、不能限制某個專案能用什麼、金鑰散在各處換不動。

現在中間多了一台**閘道**。專案改成打閘道，閘道拿真金鑰去打上游。於是每一筆呼叫都留下「哪個專案、哪個模型、多少 token、多少錢」。這個後台就是看那些紀錄的地方。

### 你固定要做的三件事

| 什麼時候 | 做什麼 | 在哪一頁 |
|---|---|---|
| 有新專案要用 AI | 發一把虛擬金鑰、填兩個對應欄位 | 應用程式 |
| 每週一次 | 看花費有沒有異常變化、橋接還活著嗎 | 總覽、通道與用量 |
| 訂閱扣款後 | 把信用卡帳單的實際金額填進去 | 訂閱 |

其餘的頁面都是「有疑問時才去查」，不需要定期看。

### 第一次進來，先看這三個地方

1. **總覽最上排四格**——這個月花多少、跟上期比、訂閱月費多少、免費額度還剩多少。
2. **應用程式**——目前有哪幾個軟體在用，各自花了多少。
3. **通道與用量**的上半「通道現況」——每一條路現在通不通。橋接是紅的話，所有走訂閱額度的模型都是斷的。

## 接一個新專案進來

從按下「新增軟體」到那個專案第一次成功呼叫，共六步。**第 1 到 4 步與第 6 步在這個後台做，只有第 5 步要交給專案那邊。**

### 第 1 步：發金鑰

「**應用程式**」頁最上面的「新增軟體」面板，填**名稱**後按「新增軟體」。描述可以不填。

名稱就是這把金鑰在閘道上的別名，**全站不能重複**，用專案的英文代號即可（例：`date-ads-analyzer`）。

### 第 2 步：把金鑰複製走

送出後會跳出一個對話框，裡面是一串 `sk-` 開頭的金鑰。

**這串字只會出現這一次。** 系統只存雜湊值，關掉之後任何人都拿不回來，包含這個後台。對話框裡有兩顆按鈕：

- **複製金鑰**——只複製那串 `sk-`。
- **複製接入範例**——連同兩個網址一起複製，貼給專案端最省事：

```
OpenAI 相容 base URL: https://llm.example.com/v1
Gemini 原生 base URL: https://llm.example.com
Authorization: Bearer sk-...
```

先按複製、確認貼得起來，再關對話框。

### 第 3 步：填「看板名」與「帳單標籤」

回到同一頁下面的「**訂閱橋接**」面板，找到剛才那一列，右邊有四顆按鈕。**這兩個一定要填**，不填不會報錯，只會讓數字悄悄對不起來：

| 按鈕 | 填什麼 | 不填的後果 |
|---|---|---|
| **看板名** | 那個專案在專案看板上的名字，也就是它 `status.json` 的 `name`（通常是資料夾名，例 `260101-my-app`） | 專案卡上不會出現這個軟體的花費。金鑰別名與看板資料夾名是兩套命名，對不起來就掛不上去 |
| **帳單標籤** | 那個專案送給 GCP 的 `client_id` 標籤（例 `myapp_main`），多個用逗號分隔 | GCP 帳單上那筆錢歸不了戶。**改過名的專案要把舊標籤一起列出**——歷史帳單上的舊標籤不會被追溯改寫，少列就少算 |

另外兩顆是選填的：

- **備註**——寫給自己看的提醒，會顯示在那一列底下（例：「開賣前必須關閉訂閱」）。
- **複查日**——填一個日期，到期前一週總覽頁會提醒你回來檢查這個軟體的設定。

### 第 4 步：要不要開放訂閱額度（多數情況：不要）

同一列中間有四個勾選框（Claude／Codex／Gemini／產圖）。**預設全部不開放，這是刻意的**——那幾個模型吃的是你自己的訂閱額度，不該因為某個專案接上閘道就自動被吃掉。

需要開放的話，勾選、看完確認框再按。判斷標準與完整注意事項在後面「讓專案用你的訂閱額度」那一節。**不確定就先不要勾**，之後隨時能加。

### 第 5 步：專案那邊要改三個地方

把這三件事交給專案（或專案的 AI）：

1. **金鑰欄**換成剛才那把 `sk-` 開頭的虛擬金鑰。
2. **base URL** 改成上面那兩個之一（看它用哪種介面）。
3. **模型名**改成閘道的部署名，例如 `gemini-fast`、`gemini-smart`、`groq-fast`。**不是**供應商的原始型號。

**順序是先貼金鑰、再改網址。** 反過來的話中間那段時間會一直被拒收，容易誤判成沒接通。

專案端如果有「讀取可用模型」的按鈕，按下去會拿到閘道允許這把金鑰用的清單，直接從裡面挑。

### 第 6 步：回來確認真的通了

回「應用程式」頁，那個軟體那一列應該開始出現花費與 token。**還是 0 的話**，往下看「打不通的時候」。

### 兩個最常踩的坑

**一、「免費」不等於免費。** 閘道上真正走免費層的只有 `gemini-flash-free`。名字裡有 `gemini-` 的其他型號一律走 Vertex，那是隨用隨付——現在實付為零只是因為 GCP 試用抵免還在吃。

**二、`client_id` 標籤打錯不會報錯。** 標籤值只能用小寫字母、數字、底線、減號。打錯的話 Google 會原封不動收下，然後在帳單上自成一桶，歸戶就悄悄裂開。所以要求專案端用程式碼裡的固定常數，不要拿會變動的字串當標籤值。

## 打不通的時候

先看症狀，對到動作。**由上而下就是排查順序**——上面的比下面的常見。

| 症狀 | 原因 | 動作 |
|---|---|---|
| 錯誤訊息含 `expected to start with 'sk-'` | 金鑰欄還放著原廠金鑰（`gsk_`、`AIza` 之類） | 換成這個後台發的 `sk-` 虛擬金鑰 |
| HTTP 400、`no healthy deployments` | 模型名不是閘道的部署名 | 改用閘道的名字。清單見「重新同步白名單」按一下之後顯示的那 16 個 |
| 專案後台「讀取可用模型」讀到一堆選了也打不到的東西 | 那把金鑰的白名單是舊的 | 「應用程式」頁按「**重新同步白名單**」，再讀一次 |
| HTTP 403 | 打了 `sub-` 開頭的模型，但那個軟體沒被開放 | 「訂閱橋接」面板勾選對應的訂閱 |
| HTTP 429 且訊息在講額度 | 額度守門：該訂閱剩餘低於 20%，橋接主動擋下 | 等額度重設，或那支請求改走 API 模型 |
| HTTP 429、訊息含 `budget_exceeded` | 那個軟體超過了它的**每月上限** | 到「應用程式」頁提高或解除上限。**專案端不要自動重試這個錯誤**，重試只會一直被擋 |
| **所有** `sub-` 模型同時打不通 | 家用主機沒開，或開了但沒有人登入 | 開機並登入該帳號。橋接的排程是「登入時」觸發，不是「開機時」 |
| 打得通，但「應用程式」那一列花費是 0 | 那些請求沒有走閘道，或走了但用的是別把金鑰 | 看同一頁標紅的「未歸戶」那一列，量對得上就是金鑰貼錯 |
| 專案看板的卡片上沒有花費 | 「看板名」沒填或填錯 | 「訂閱橋接」面板按「看板名」，填 `status.json` 的 `name` |
| GCP 帳單頁有錢但歸不了戶 | 「帳單標籤」沒填，或專案改過名只填了新的 | 按「帳單標籤」，把所有用過的 `client_id` 都列上 |

分不出是哪一類的時候，先去「**通道與用量**」的上半：那一頁每次開啟都會現場問每一條路通不通，不是讀設定檔的副本。

## 三種金額，不要混著看

看數字之前先記住一句話：這套系統裡有**三種不同性質的金額**，混在一起看會得到錯的結論。

| 性質 | 哪裡來的 | 能不能當帳單 |
|---|---|---|
| **牌價** | 閘道（LiteLLM）用自己的價目表算的 | 對 Vertex 來說**它就是帳單的原價**，其餘供應商是估算 |
| **帳單** | GCP 的 BigQuery 帳單匯出 | 是。分「原價」與「實付」兩欄 |
| **月費** | 訂閱的固定費用，你自己登記的 | 是，但與用量無關 |

還有一個貫穿全站的陷阱：**原價不等於實付**。目前 Vertex 全額吃 GCP 試用抵免，實付是 0。所以任何「比較便宜幾倍」的結論，講的都是**抵免用完之後**的狀態，不是現在。

## 名詞：三個容易混的東西

| 名詞 | 是什麼 | 白話 |
|---|---|---|
| **真金鑰** | Google、Groq 發給你的原廠金鑰 | 信用卡本卡 |
| **虛擬金鑰** | 閘道自己發的 `sk-...`，只有閘道認得 | 附卡，刷了誰刷的一目了然 |
| **閘道** | 一台中轉站，**它本身不是 AI** | 收費站兼刷卡機 |

專案手上只有虛擬金鑰。真金鑰全部鎖在閘道裡，一個位元組都不會進到你的瀏覽器——所以這個後台**沒有辦法顯示或複製任何真金鑰**。

## 總覽

回答「這個月花了多少、跟上個月比如何、照這個速度會到哪」。

**上排四格**

- **本月 API 成本** — 閘道記到的花費，含「較上一期」與「照目前速度整期約多少」。後者是線性外推，只在期間包含今天時才出現。
- **本月訂閱月費** — 你登記的固定費用。年繳會先折算成每月等值再加總，不會被當成十二倍。
- **總 Token** — 閘道記到的量，不含沒走閘道的直連。
- **免費額度剩餘** — **只計經閘道消耗的量**，日界線是台北時間。同一把免費金鑰若在閘道以外被用掉，這裡看不到，所以這是下限不是實際剩餘。

**每百萬 token 的等效成本** — 整套軟體存在的理由：回答「訂閱划不划算」。要注意 token 數含大量快取讀取（實測某一輪 94.6%），而 API 那側快取也比較便宜，所以這個比較**偏向對訂閱有利**。它回答的是「同樣的 token 量」，不是「同樣的錢買到的價值」。

**訂閱省下多少** — 同樣的 token 若走官方 API 要付多少，減掉訂閱月費。Claude 的快取寫入有兩種價：5 分鐘 1.25 倍、1 小時 2 倍輸入價，2026-09-10 起分開計算（Claude Code 在 Opus／Fable 上的寫入九成九是 1 小時的，以前一律按 5 分鐘算，少算了一成七）。**還沒更新用量收集器的電腦**回報的資料缺 1 小時那一欄，那一段仍按 5 分鐘價算，所以這個數字偏保守。更新方法見 repo 裡 `collector/README.md`：重跑 `1-安裝.bat`，它會自動把舊資料重送一次。

**Vertex 用量** — 資料來自 GCP Cloud Monitoring，那是**專案層總量、包含經過閘道的部分**，所以**不能跟上面的閘道統計相加**，會重複計算。要看閘道與直連各佔多少，去 GCP 帳單頁的對帳面板。

## 營運大屏

任何一頁頁首的「**切換到大屏**」。全畫面、給電視牆或第二螢幕用的版本，每 60 秒自動更新；頁首的「**返回儀表板**」回到這裡。

| 區塊 | 回答什麼 |
|---|---|
| 上排三格 | 本月呼叫次數（含失敗）、本月 token、本月閘道花費（美元＋台幣） |
| 中央「流量拓撲」 | 左邊是軟體、中間是閘道、右邊是實際打到的模型。線越粗呼叫越多；失敗的請求單獨一類，不混進模型 |
| 近 24 小時每小時呼叫 | **往回滾 24 小時**，不是「今天」——午夜剛過也看得到昨晚的量 |
| 免費額度 | 各免費池今天用了多少；上限跟著閘道實際掛的金鑰數自動算 |
| 軟體費用排行、訂閱省下多少 | 與「應用程式」「總覽」同一套算法，數字對得上 |
| 最近異常 | 失敗的請求翻成白話（錯誤訊息裡的金鑰片段會遮掉）與預算告警；同一分鐘同一件事合併成「×N」 |

- **兩種外觀**（2026-09-12 起）：大屏頁首的「**風格**」按一下換下一種——**藍紫科幻**與**黑橘警戒**，這台電腦會記住。儀表板頁首的「切換到大屏」也是按一下換下一種。網址可以直接指定：`/bigscreen?skin=nerv`、`/bigscreen?skin=cyber`，電視牆存書籤或開機頁用這個。兩種外觀的資料完全一樣，只有配色與造型不同。
- 導覽列不再有「大屏」那一格（同一個功能兩個入口，重複了）；入口只有頁首那顆。
- **動態效果**在頁首切換：**開／關**，這台電腦會記住。覺得畫面在動很干擾，選「關」。沒選過的話，若你的系統設定要求減少動態效果，第一次打開就是「關」。
- **全螢幕**在同一排。
- 每一塊右下角的小字（`SRC · …`）是那塊資料取自哪張表，數字對不起來時從那裡查。
- 軟體的顏色依建立順序固定分配，**不照排名**——排名每天在變，同一個軟體不會因此換色。

## 專案看板

每個專案一張卡，狀態、分類、開發週期、以及該期間的 AI 花費。

**看板的資料是怎麼進來的**（第一次用一定要先做這一步，否則頁面是空的）

看板不會自己去掃你的電腦。它讀的是**每個專案 repo 裡的 `doc/status.json`**，所以要先有人把那個檔生出來、再推上來：

1. **讓 AI 幫你寫那個檔**：把 `claude-skill/update-project-status` 整個資料夾複製到 `%USERPROFILE%\.claude\skills\`，之後在任何專案裡對 Claude Code 說「更新進度」。
2. **讓每台電腦自動推送**（順便可以從看板一鍵開啟專案）：照 `helper/README.md` 裝一次本機小幫手。
3. **讀 GitHub 上的 repo**：在 `.env` 填 `GITHUB_TOKEN`（只要讀取權限），主機端排程會定時同步。

完整步驟在 `INSTALL.md` 第 11 節。這三件都是選用的——不裝看板，其他功能照常運作。

卡片上那筆花費會跟著右上角的日期選單走。兩個數字（閘道與帳單）**部分重疊，不要相加**。

**欄位紀律**（這幾條是為了讓卡片能被讀，不是形式）

- **進度說明**上限約 500 字，只寫現況摘要。完整開發紀錄屬於專案自己的 `doc/backup-*.md`。
- **備註只有你會寫**，AI 不會動它。
- **分類**從編輯視窗的下拉清單挑，不要每個專案自己發明。

## 應用程式

發虛擬金鑰、看每個軟體花了多少。**新接一個專案進來的完整步驟在前面「接一個新專案進來」那一節**，這裡補充那六步沒講到的部分。

**新增軟體**會簽發一把虛擬金鑰，**只顯示這一次**。系統只存雜湊，關掉之後任何人都拿不回來，包含這個後台。所以那個視窗有「複製金鑰」與「複製接入範例」兩顆按鈕，先按再關。

**「訂閱橋接」面板每一列右邊的四顆按鈕**：

| 按鈕 | 用途 | 必填？ |
|---|---|---|
| **備註** | 寫給自己看的提醒，顯示在那一列底下 | 選填 |
| **複查日** | 到期前一週，總覽頁會提醒你回來檢查這個軟體 | 選填 |
| **看板名** | 對應到專案看板的卡片（填 `status.json` 的 `name`） | **要填**，否則卡片上不會有花費 |
| **帳單標籤** | 對應到 GCP 帳單的 `client_id`（多個用逗號分隔） | **要填**，否則帳單上那筆歸不了戶 |

後兩個沒填時，那一列底下會直接寫「看板名 未填」「帳單標籤 未填」——看到就補。

**封存**會立即撤銷該軟體的虛擬金鑰，之後它的請求一律被拒。**此動作無法復原**，歷史花費仍然留著。專案確定不再使用時才按。

**弄丟了怎麼辦** — 按該列的「重新簽發」。舊金鑰立刻失效，要把新的貼到**那個專案裡每一個貼過金鑰的欄位**（各家供應商區塊都是同一把，因為閘道是看模型名稱路由，不是看金鑰）。**其他專案不受影響**，每個軟體各有各的金鑰。

換金鑰之後，那個軟體**過去的花費仍然歸在它名下**——舊金鑰會被記進 `retired_vkey_ids`，歸戶時一起比對。

**標紅的「未歸戶」那一列**是對不回任何軟體的請求，多半是 master key 直接打或已撤銷金鑰的殘留。沒有這一列的話，上面的數字看起來就像全部，真的有東西在偷打也不會有人發現。

**每月上限**（2026-09-10 起）——每一列的「**每月上限**」按鈕。用台幣或美金輸入都可以，兩個數字會並列顯示給你確認。

- 上限以**美金**存在閘道上，實際擋下的點就是那個美金數字。台幣是按目前匯率換算的參考值，匯率變動時畫面上的台幣會跟著變，美金上限不會。
- 超過之後閘道**直接拒絕、不轉發給供應商**，那個專案收到 **HTTP 429**（`budget_exceeded`）。**請專案端把這個錯誤當成不可重試**：一般程式把 429 當成「太頻繁、稍後重試」，會一直重打。
- **每月 1 日 00:00（台北時間）歸零。**
- 設定時會把「本期已用」同步成本月實際花費，不會因為這把金鑰以前花過錢就當場被擋。你輸入的上限若不高於本月已用，對話框會先警告。
- 重新簽發金鑰時，上限會自動套到新金鑰上。「解除上限」在同一個對話框裡。

## 讓專案用你的訂閱額度

閘道上有四個 `sub-` 開頭的模型，它們不打 API、**直接吃你自己的訂閱**：

| 模型名 | 吃哪個訂閱 |
|---|---|
| `sub-claude` | Claude（與你自己的 Claude Code 同一個池） |
| `sub-codex` | ChatGPT（與你自己的 Codex 同一個池） |
| `sub-gemini` | Google（Antigravity，同一個池） |
| `sub-imagegen` | Codex 的內建產圖，吃 ChatGPT 的池 |

**預設全部不開放。** 新簽發的金鑰打這幾個模型會被回 403
（`key_model_access_denied`），這是刻意的——訂閱額度是你自己在用的，
不該因為某個專案接上閘道就自動被吃。

> **2026-08-28 之前這句話其實不成立。** 發鑰時沒有一併寫入白名單，
> 而 LiteLLM 把「空白名單」當成**全部放行**，所以那之前新建的軟體
> 一發鑰就打得到這四條。已修（發鑰當下就套白名單），並用拋棄式軟體實打驗過。
> 現有的六個軟體都在更早之前同步過白名單，沒有受影響。

### 開放步驟

1. 到「**應用程式**」頁，找到「**訂閱橋接**」面板。
2. 找到那個軟體那一列，勾選要開放的訂閱（Claude／Codex／Gemini／產圖）。
3. 勾的時候會跳出確認框，**看完再按**：訂閱的速率限制是全帳號共用的，
   若那個軟體有其他人在用，他們的請求也會吃你的額度。
4. 儲存後會即時推送到閘道的金鑰白名單。推送失敗會顯示警告——
   「設定看起來對但實際沒生效」是最危險的狀態，所以那個警告不要忽略。
5. 專案那邊把模型名改成 `sub-claude` 之類即可，網址與金鑰都不用動。

### 開放之前要知道的五件

**一、每次呼叫有一萬多個 token 的固定開銷，跟你的問題多短無關。**
2026-08-28 從 VPS 逐一實打：

| | 一次呼叫的固定 prompt tokens | 延遲 |
|---|---|---|
| `sub-claude` | **12,639** | 5～13 秒 |
| `sub-gemini` | **16,453** | 約 11 秒 |
| 對照：`gemini-2.5-flash`（走 API） | 6 | 0.95 秒 |

那一萬多是 CLI 自己的系統提示，每一次都重送、每一次都算進你的訂閱額度。
**這是決定要不要開放時最該看的數字**：一個每天叫 200 次的功能，
走 `sub-claude` 等於每天燒掉 250 萬個訂閱 token，走 API 是 1,200 個。

**二、額度見底時會被擋，而且是刻意的。** 訂閱剩餘低於 **20%** 時，
橋接一律拒絕請求並回一個說明原因的 429。那道閘是為了把最後的額度留給你自己用——
橋接跑一整天的批次就能把週額度用光，然後你要用時發現沒了。

**三、它需要家用主機開著。** `sub-*` 走的是家裡那台機器上的橋接服務，
不是雲端。機器關機、或關機重開但沒有人登入，這幾個模型會全部打不通
（橋接的排程是「登入時」觸發，不是「開機時」）。通不通看「通道與用量」頁。

**四、多輪對話是有損的。** 內容不會少，但結構會被壓平，也拿不到前綴快取的效益。
當成單次任務用沒問題，當成長對話用會比走 API 貴（貴在 token 數，不是錢）。

**五、產圖不能指定模型也不能控制尺寸**，而且換不出「同一張臉」。上游限制，不可修。

### 什麼時候該用、什麼時候不該

訂閱是**固定月費**，用多用少都一樣錢，所以拿來跑「量大但不急、失敗可以重來」的
批次工作最划算。反過來說，**線上使用者在等的請求不要走 `sub-*`**——
它要排隊（橋接同時只跑一個請求）、依賴家用主機、而且額度見底時會直接被擋。
那種請求該走 API，貴一點但穩定。

## 換模型（要更聰明的，或更省的）

**模型是每一次呼叫時指定的，不是綁在金鑰上。** 一把虛擬金鑰可以打很多模型，
專案要換模型只要改送出的 `model` 名字，金鑰、網址都不用動，也不必多發一把。

### 建議用這兩個名字

| 名字 | 預設指向 | 什麼時候用 |
|---|---|---|
| `gemini-fast` | gemini-3.1-flash-lite | 一般任務、量大的、對答速度要緊的 |
| `gemini-smart` | gemini-3.1-pro-preview | 要推理、要長文理解、品質不夠好的那幾個環節 |

這兩個是**用途別名**。以後出了更強的模型，只要改閘道設定裡這兩行指向哪一支，
所有專案自動跟著升級，不必一個一個改程式。**專案請盡量只認這兩個名字。**

### 直接指定型號時的價差

| 部署名 | 輸入（USD／百萬） | 輸出（USD／百萬） |
|---|---|---|
| gemini-3.1-flash-lite | 0.25 | 1.5 |
| gemini-2.5-flash | 0.3 | 2.5 |
| gemini-2.5-pro | 1.25 | 10 |
| gemini-3.1-pro-preview | 2.0 | 12 |

**pro 比 flash-lite 貴約八倍，而且它會產生看不見的思考 token，也算輸出費用**——
實測問「2 加 3 等於多少」，回一個「5」，輸出記了 156 個 token。
只換需要動腦的環節，不要整個專案全換。

Vertex 上 3.x 的 pro 要用 **`-preview` 結尾**的名字才叫得到，
`gemini-3.1-pro`、`gemini-3-pro` 都是 404。

### 換完要確認

1. 回「應用程式」頁看那一列的花費有沒有開始跳。
2. 被回 403 且訊息在講模型清單，表示那把金鑰的白名單還沒有這個名字——
   到「應用程式」頁按「重新同步白名單」。

## 看一把金鑰能用哪些模型

在「金鑰管理」頁，每一把金鑰底下都有一列可以展開的 **可用模型**。點開會看到：

1. **這把金鑰在供應商那邊實際能用的模型，依用途分組**：文字、生圖、語音、影片、嵌入、音樂。
   分組是因為名字看不出用途——`gemini-3.1-flash-image` 是畫圖的、`whisper-large-v3` 是聽寫的、
   `gemini-embedding-2` 根本不會回話。每個名字後面還會標能力（看圖、聽語音、讀影片、思考）。
2. **粗體的是閘道正在用的那幾個**。
3. **最上面的紅框是「要處理」的事**，只有兩種會出現，而且只講閘道真的在用的：
   - **要換掉**：供應商清單上已經沒有這一支了。
   - **快到期**：供應商宣告了停用日期，而且剩不到四個月。

### 「快到期」是怎麼知道的

老實說：**大部分供應商不講**。實際問過的結果是——

| 供應商 | 會不會說要停用 |
|---|---|
| OpenRouter | 會，有明確到期日 |
| Vertex AI | 只說是正式版還是預覽版，沒有日期 |
| Groq | 只有一個開關，沒有日期 |
| Gemini API | 完全不說 |

所以畫面上的日期，來源只有兩種：供應商自己宣告的，或是**拿 OpenRouter 上同名模型的日期當參考**。
後者會寫成「OpenRouter 宣告」，那不是原廠公告，只是目前唯一拿得到的訊號。
沒有日期的模型不代表安全，只代表沒人講。標成「預覽版」的隨時可能被換掉。

### 金鑰失效的話

查不動的金鑰不會列模型，會直接在那一列標紅字「金鑰已失效」。
這件事很重要：閘道輪替金鑰時**不會跳過壞掉的那一把**，留著會變成間歇性失敗，是最難查的那種。
確定不用了就用同一列的「移除」，或在閘道設定裡把它註解掉。

清單由主機端每 6 小時抓一次（`scripts/fetch-upstream-models.py`），標題列會顯示抓取時間。
**金鑰值不會進到網頁**：主機端只把模型名稱寫進檔案，儀表板讀那個檔。

## 限制某個軟體只能用哪些模型

在「應用程式」頁，每一列有一個「**模型**」按鈕。裡面有兩個設定：

**一、可用模型**（勾選）
清單一樣**依用途分組**，每組上面有一句說明（例如「生圖：產生圖片，收費方式與文字模型不同，通常貴很多」）。
沒動過就是全部放行。取消勾選之後，那個軟體打被取消的模型會收到 HTTP 403。
用途是把貴的模型只留給需要的軟體，例如只有某一個專案能用 pro。

訂閱通道（`sub-` 開頭）不在這裡設定，那要走同一頁下面的「訂閱橋接」面板——
**這裡的設定不會動到已經授權的訂閱通道**。

**二、預設模型**（選填）
選了之後，那個軟體只要送 `default` 這個名字，就會打到你選的模型。

好處是**以後要換模型，改這裡就好，專案一行都不用動**。
專案端一次把模型名設成 `default`，之後升級模型、降級省錢都在這個後台決定。

不用這個機制就留「不指定」，專案照常送實際的模型名。

## 模型白名單與「重新同步」

每把虛擬金鑰都有一份**允許使用的模型清單**。專案後台按「讀取可用模型」時，
閘道回的就是這份清單。打清單以外的模型會被回 403 `key_model_access_denied`，
而那個錯誤訊息會把准打的清單整份列出來——那是排錯最快的資訊。

**新增軟體時會自動套上這份清單**（2026-08-28 起）：16 個非訂閱模型全放行、
四條 `sub-*` 全擋下。若簽發對話框出現「模型白名單沒套上」的警告，
表示當下閘道連不上、那把鑰暫時是全開的，按一次「重新同步白名單」補上。

**閘道新增或改名模型之後，要按一次「重新同步白名單」**
（在「應用程式」頁的「訂閱橋接」面板右上角），既有軟體才能用到新模型。
不按不會壞掉，只是新模型還沒開放而已。

2026-08-26 之前這份清單存的是萬用樣式（`gemini-*`、`groq-*`…），
結果專案後台讀到的是一堆**打不到的樣式與展開的 Vertex 型錄**（96 筆裡 91 筆是雜訊），
真正能用的名字一個都不在裡面。現在改存明確的部署名，讀到的就是能直接選的 16 個。

`vertex_ai/*` 是例外，只給真的需要 **Vertex 直通**的軟體保留——
直通的模型名是 Google 型錄那一整套，列不完。代價是那個軟體的清單會多出上百筆，
所以不需要直通的不要開。

## 金鑰管理

**上游**金鑰的盤點——供應商那一側的真金鑰。發給專案的虛擬金鑰在「應用程式」頁，兩者不要混。

這一頁顯示的是環境變數的**名字**（`GEMINI_FREE_KEY_3` 這種），不是金鑰值。那不是機密，而且它才是輪換時真正要找的東西：知道「第三把在燒」但不知道它叫什麼，等於沒說。

**免費額度**面板可以直接改上限。三件事講清楚否則數字會被誤讀：

1. **只計經本閘道消耗的量**，不等於供應商端的實際剩餘。
2. 日界線是**台北時間當日**，與供應商的重設時點不一定一致（Google AI Studio 是太平洋時間午夜）。
3. **每日 token 上限（TPD）目前是空的**，所以 token 進度條畫不出來。不是漏做：AI Studio 免費層沒有這個維度，Groq 有但閘道拿不到那個標頭。
4. **把數跟著閘道設定自動算**（2026-09-12 起）。新增或移除一把金鑰之後，整池上限自動跟著變，不用再手改。只有閘道設定讀不到時，才會退回手填值，並寫明「暫用手填值」。

### 新增與移除上游金鑰

- **新增**：「新增上游金鑰」面板，選供應商、選要加進哪個模型組、貼上金鑰。送出前會先拿這把金鑰去打供應商驗證，**驗不過不會寫進任何地方**。變數名系統會自動推（例：已有 `GEMINI_FREE_KEY_1`～`_7` 就帶 `_8`），通常不用改。
- **移除**：明細每一列右邊的「移除」。那把金鑰會移出輪替，`.env` 那一行改成註解——**值留著，按錯救得回來**。**模型組的最後一把不給移**，移掉會讓整個模型從閘道消失。
- 兩者都是排進佇列、由主機每分鐘處理一次。**套用時閘道會重啟數秒**，那段時間的請求會失敗，尖峰時段不要按。套用失敗會自動回滾並把閘道重新拉起來，結果顯示在面板下方的紀錄表。
- 每一把旁邊的 `…XXXX` 是金鑰**尾 4 碼**，去供應商後台停用時用它對。
- **要讓金鑰真正作廢，還是得去供應商後台停用**——這裡的「移除」只是閘道不再使用它。順序是**先在這裡移除、再去後台停用**；反過來的話，閘道還掛著那把已停用的金鑰，會出現間歇性 401。

## 訂閱

登記訂閱月費，以及**扣款當天的匯率凍結**。

**扣款歷史**存的是「已經發生的事」，用當天的匯率寫死，之後不再重算。不這樣做的話，回頭看上個月的台幣金額會被這個月的匯率改寫，跟信用卡帳單永遠對不起來，而且對不起來時分不清是匯率造成的還是漏記造成的。

**實際入帳**要你自己填。填三次左右，系統就能從「預期 vs 實際」反推出真正的手續費率，取代目前猜的 1.5%。

**匯率與手續費**在頁尾。這個匯率只用於**尚未發生**的預估；已扣款的用當天凍結的值。GCP 帳單本身即為台幣計價，不經過換匯。

## 預算告警

設月預算，超過門檻寄信。

「閘道 ＋ Vertex 直連估算」這個選項要知道它算什麼：Vertex 的專案總量**扣掉經閘道的部分**才是直連。不扣的話經閘道的 Vertex 會被算兩次。

單一軟體的預算只計經閘道的用量——直連目前分不出軟體，未計入。

## 通道與用量

上半「**通道現況**」回答「有哪些路、現在通不通」，每次開頁都重新現場問，不是讀設定檔的副本（副本會漂移）。

下半「**通道用量**」回答「那些路跑了多少」。

**橋接**是家用主機上的一支服務，讓閘道能用訂閱額度（`sub-*` 模型）。它斷了的話所有 `sub-*` 會全部打不通，而這一頁是唯一看得出來的地方。

**額度守門**：訂閱剩餘低於 20% 時，橋接的請求會被擋下並回一個說明原因的 429。那是刻意的——橋接與你自己用的是同一個池，這道閘是為了不要讓批次把你要用的額度用光。

## GCP 帳單

Google 實際收的錢。

**原價（gross）vs 實付（net）** 一定要分開看。抵免期間 net 會是零，只看它會以為沒花錢。

**Vertex 對帳：閘道與直連** 這一格把三套彼此獨立的成本數字接起來。已查證的對應關係：

```
帳單裡的「(未標示)」 ÷ 閘道牌價 = 32.375
```

連續四天誤差 0.01%。也就是說**閘道牌價不是帳單的估計值，它就是帳單的 gross**，差別只在抵免。帳單上帶 `client_id` 標籤的那些則是沒走閘道的直連。

**閘道涵蓋率**告訴你有多少比例的 Vertex 用量真的經過閘道。沒經過的那部分，額度守門與單位成本都管不到。

## 日期選單（右上角）

「本月／上月／自訂」。**自訂**兩端都包含在內，最多 366 天。

**月份與日界線一律用台北時間**（2026-09-12 起）：「本月」是台北時間每月 1 日 00:00 起，每月上限在同一個時點歸零。以前是 UTC 月份（台北要到 1 日早上 8 點才換月），所以月初凌晨那幾個小時的呼叫，改版前後會歸在不同的月份。

這個選單只在會依日期改變內容的頁面出現：總覽、專案看板、應用程式、通道與用量、GCP 帳單。其他頁面沒有月份概念，所以那裡不會顯示它——一顆按了不會有事的按鈕不該出現。
